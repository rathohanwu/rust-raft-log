Design at a glance

Consensus core

RaftNode owns Raft roles, terms, votes, log matching, replication progress, and commitment.

Durable storage

Memory-mapped segments store the log; a separate metadata file stores the current term and vote.

Event-driven ownership

One actor thread serializes every Raft mutation, while Tokio handles concurrent outbound RPC I/O.

Application boundary

An optional deterministic state machine observes committed commands without becoming part of the protocol.

  • Persist a changed term or vote before returning a response that relies on it.
  • Persist changed follower log data before acknowledging AppendEntries success.
  • Commit only entries from the leader's current term after they reach a quorum.
  • Fail-stop after a persistence or storage-invariant failure instead of acknowledging unsafe progress.

Event-driven actor pattern

The service layer assigns IDs and forwards work. The actor receives all event sources in one queue, calls the synchronous Raft core, and publishes outbound work without sharing mutable Raft state.

State-machine contract

What is applied

Only committed Normal log entries call StateMachine::apply, once and in index order. Raft NoOp entries advance last_applied without calling the application.

Execution model

apply runs synchronously on the actor thread. It must be deterministic, fast, and free of blocking I/O or re-entrant Raft calls.

Recovery boundary

Raft persists the log and hard state, not application snapshots. On restart, state machines rebuild only as a committed prefix becomes known.

Observation

state_snapshot is optional. GetAppliedState is a test/debug RPC and is unavailable on the production binary without an embedded machine.

Durability is part of the protocol boundary: changed hard state is flushed before the related response, and changed follower log data is flushed before AppendEntries success. If a required persistence operation or storage invariant fails, the node fail-stops instead of acknowledging normal Raft progress. The application state machine is optional and runs synchronously on the actor thread only for committed Normal entries.
